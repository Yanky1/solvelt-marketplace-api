# Brief M3: cart and checkout (API + web)
**Depends on:** M1 (SignedPortalClient incl. orders/shipping/local-delivery/payment-events methods, webhook receiver, outbox, auth + guest), M2 PDP (add to cart), W1 auth.
**Cart:** server-side cart per buyer or guest (cookie id), merge on sign-in; lines reference listing + variant; price/stock re-validated on every view and at checkout; **split per (seller, brand)** into groups exactly as the portal splits seller orders; services are not cart items (M4).
**Shipping per group:** `GET /shipping/settings` (cached) → speeds and prices computed per CONTRACT.md §5 (flat, weight-based, free threshold on that group's items subtotal), handling days → delivery estimate. **Local delivery:** `POST /local-delivery/eligibility` per group → windows; buyer picks a window; re-checked on ingest.
**Tax:** a `ITaxCalculator` with a documented simple policy (US: per-state rate table in config applied to items + shipping where taxable; record the decision; no live tax provider) — per line `taxCents`, rounding documented.
**Payment:** Stripe on the platform account, **test mode**, Payment Intents + Payment Element (3DS/SCA), one intent for the whole checkout; amounts computed server-side only; idempotency keys on every Stripe call; a fake provider in CI; Stripe webhook endpoint (own signing secret `Stripe:WebhookSecret`) handling `payment_intent.succeeded|payment_failed`, `charge.refunded`, `charge.dispute.*`, idempotent on event id, order-independent.
**Order flow:** checkout creates our `MarketplaceOrder` (`MP-…`) as PendingPayment → on `payment_intent.succeeded` ingest `POST /orders` (idempotent on `marketplaceOrderId`) → store seller orders → send `payment.captured` via our outbox. `422 invalid_order` or a local window gone → automatic full refund + buyer email + order marked failed. Oversold → accepted by portal; show it. Refunds: on portal `refund.issued` / `order.cancelled.refundDueCents` → Stripe refund (idempotent on the portal refund id) → `refund.processed` per seller order. Disputes → `dispute.*` to the portal mapped to the seller order(s).
**Web:** cart page and mini-cart, checkout (address book or guest address, per-group shipping speed / local window, order summary with per-seller groups, tax, total), Payment Element in light/dark theme, 3DS handled, confirmation page, order emails (`IEmailSender`).
**Tests:** parallel double-submit of checkout creates one order and one charge; webhook replays; ingest retried after timeout yields one order; refund never exceeds paid; money sums per group equal the intent amount; a client-supplied price/total is ignored.
