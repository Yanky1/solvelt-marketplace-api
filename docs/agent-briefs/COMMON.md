# Common rules for every buyer-marketplace worker (inline this with every brief)

* **Approved assignment** from the repository owner (CLAUDE.md in both repos). Never end your turn to ask a question: decide, record the decision
  (API: `docs/DECISIONS.md`, ids `<WS>-nn`; web: `docs/DESIGN.md`), continue. Schedule your own `send_later` check-ins (~30 min).
* **Repos:** API Yanky1/solvelt-marketplace-api (ASP.NET Core 10, EF Core, PostgreSQL prod / SQLite tests, xUnit), web Yanky1/solvelt-marketplace-web
  (React Router v7 framework mode SSR, TypeScript, Vitest+RTL+MSW, Playwright+axe). Attach the sister repo with `add_repo` (owner `Yanky1`, access `push`).
  Seller-portal repos Yanky1/Yanky1-test-login-backend and Yanky1/test-login-frontend: **read-only** (`add_repo` access `read`) for contracts and patterns. Never touch any other repo.
* **Read first:** CLAUDE.md, `docs/CONTRACT.md` (API repo; how every portal contract is consumed/produced: follow it exactly), `docs/API.md`, `docs/DECISIONS.md`, `docs/AGENTS.md`, and in the web repo `docs/DESIGN.md`. Reuse what M1/W1 built (SignedPortalClient, fake portal, webhook receiver + projection framework, outbox, auth/sessions, BFF API client, design-system components). Don't build a second one.
* **Merging:** feature branch per slice (`feat/<ws>-<slice>`), rebased on current origin/main, every workflow green on that exact commit (CI; plus E2E on web), no test skipped/deleted/weakened, fast-forward push (or rebase-merge PR if push is refused). Never force-push, never merge commits, never rewrite a pushed branch (push a new name). Small slices; API slice before the web slice that uses it.
* **Never:** change seller-portal code (contract changes go to the orchestrator, session_018hZb8pE5JAKd7eu3Enzfnr, via send_message); commit secrets; use live Stripe/Shippo keys. Stripe: test mode only, keys only from env, a fake provider in CI.
* **Review hotspots (checked on every merge):** client-controlled time values; matching across accounts by external ids (match on our ids + portal ids, never tracking numbers/SKUs alone); idempotency under parallel requests (write concurrency tests); PII retention + redaction of every new field/file (extend the PII table in DECISIONS); signing keys never reused across purposes; local/session storage cleared at the right moments; dark-mode contrast (axe in light and dark); `Cache-Control: private` on personalised SSR; CSRF on every action; money in `long` cents, no floats; another user's resource is 404.
* **Each merge:** a test that fails without the change for every regression-relevant behaviour; update your row in `docs/AGENTS.md`; screenshots (desktop + mobile, light + dark) for new web pages in `docs/screenshots/`; report to the orchestrator (send_message; if unavailable, in your final message) with sha, tests added, next, blocked.
