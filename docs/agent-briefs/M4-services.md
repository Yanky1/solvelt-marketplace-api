# Brief M4: services and bookings (API + web)
**Depends on:** M1 portal client + receiver, M2 service page, M3 payments (Stripe intent + payment.captured with booking kinds).
**API:** availability proxy `GET /services/{id}/availability` (≤ 62 days, coalesced + cached ≤ 30 s, because the portal rate limit is per service for all shoppers), location options online/customer(at-home: address + lat/lng, service-area errors)/seller, add-ons, provider choice when `buyerChoice`, intake questions; holds (`POST /bookings/holds`, 10-minute hold shown as a countdown) → payment → confirm; instant vs request-to-book (`booking.requested` → await `booking.confirmed`/`declined`, release/refund on decline or `hold_expired`); reschedule requests, buyer cancellation with policy fee (`cancellationFeeCents` charged, `refundDueCents` refunded), proposed times (accept/decline), additional-charge requests (**buyer consent required** before charging), no-show fees, quotes (request → `quote.sent` → accept/decline → book), booking messages, reminders from `booking.reminder` (email). Receiver handlers for every `booking.*`/`quote.*` event, order-independent; online meeting link only shown to the confirmed buyer.
**Payments:** `payment.captured` kinds `booking`, `booking_cancellation_fee`, `booking_no_show_fee`, `booking_extra_charge`; refunds via `refund.processed` with `marketplaceBookingId`.
**Web:** booking widget on the service page (calendar with time-zone display of the provider vs buyer, slot list, location + address, add-ons, intake form), checkout for bookings, booking detail page (status timeline, reschedule, cancel with the fee shown before confirming, respond to proposals and extra-charge requests, messages, add to calendar .ics), quotes flow.
**Tests:** two buyers holding the same slot in parallel → one wins; client-supplied start time/price ignored beyond the portal-validated slot; time zones/DST around the slot list.
