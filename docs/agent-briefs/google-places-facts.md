# Google Places API (New): the facts the address-help adapter is built from

Read by the orchestrator on 2026-11-26 from developers.google.com, Places API (New) pages named: place-autocomplete, using-session-tokens, session-pricing, place-details, data-fields, policies, get-api-key, api-security-best-practices (the exact URL paths were not passed on; they are under developers.google.com/maps/documentation/places/web-service). Passed to the voice worker in a cross-session message; copied here. Anything marked **NOT STATED** is not in the code, or is behind an owner decision. Legacy Places "can no longer be enabled for new Google Cloud projects" (as of October 2026): only Places API (New) is used.

## Autocomplete (New)
- `POST https://places.googleapis.com/v1/places:autocomplete`, JSON body. Headers `Content-Type: application/json`, `X-Goog-Api-Key: KEY`. `X-Goog-FieldMask` is optional here (comma separated, "Spaces are not allowed anywhere in the field list", `*` = all).
- Body: `input` (required); `includedPrimaryTypes` ("up to five" types from Table A/B, or one of `(regions)` / `(cities)`; INVALID_REQUEST for more than five, another type next to (cities)/(regions), or an unrecognised type; matches the PRIMARY type only); `includedRegionCodes` ("up to 15" two-character ccTLD codes; `uk`, not `gb`); `languageCode` (BCP-47; default Accept-Language or `en`); `regionCode` (ccTLD; for formatting and bias; invalid gives INVALID_ARGUMENT; inside that region the country may be left out, so `structuredFormat.secondaryText` might not be present); `locationBias` OR `locationRestriction` (circle or rectangle, never both; with neither the request is IP-biased, which would be OUR server's IP: send a region); `sessionToken`; `inputOffset`; `includeQueryPredictions` (default false).
- Response: `suggestions[]` holding `placePrediction { place: "places/ID", placeId, text { text, matches[{endOffset}] }, structuredFormat { mainText { text, matches }, secondaryText { text } }, types[] }` or `queryPrediction`. "Up to five placePredictions" when `includeQueryPredictions` is unset. The prediction text "may include alternative names" that differ from Place Details' address for the same place id, and may be in another language: read back the DETAILS address before the caller confirms, not the prediction text.
- **NOT STATED:** which types to put in `includedPrimaryTypes` for street addresses (the type tables were not fetched). The adapter leaves `includedPrimaryTypes` out.

## Session tokens (New)
- "Google recommends using version 4 UUIDs"; unique per Cloud project. A session "starts with the first Autocomplete (New) request that includes a session token" and is "terminated by a request to Place Details (New) or Address Validation that uses the session token". After termination, reusing the token is "billed as if there was no session token". An abandoned session expires; only the autocomplete requests are billed ("SKU: Autocomplete Requests").
- Billing when the session ends in Place Details Essentials fields: the first 12 autocomplete requests are billed per request, 13 and higher are free, plus the Details Essentials charge. Ending with Details "Essentials (IDs Only)" makes all autocompletes per-request.
- **NOT STATED:** the session lifetime in minutes. Design: one token per address-capture attempt in a call; a fresh token after a Details call or an abandon (the adapter also replaces a token idle for ten minutes: our own bound, not Google's).

## Place Details (New)
- `GET https://places.googleapis.com/v1/places/PLACE_ID?sessionToken=TOKEN` (`languageCode` and `regionCode` are also query parameters). Headers `X-Goog-Api-Key` and `X-Goog-FieldMask`, which is REQUIRED ("There is no default list of returned fields ... If you omit the field mask, the method returns an error"). `languageCode` defaults to `en`; invalid gives INVALID_ARGUMENT; if the country matches `regionCode` it is omitted from `formattedAddress`.
- Fields: `addressComponents`, `formattedAddress`, `postalAddress`, `location`, `types` (optionally `shortFormattedAddress`) are all "Place Details Essentials". Do NOT request `displayName` (Pro). The adapter asks only for what it uses: `addressComponents,formattedAddress,postalAddress` (no location, no types: not needed, and the location's storage is limited by the terms).
- **NOT FETCHED in detail:** the exact sub-field names of `addressComponents` and `postalAddress` (the data-fields page lists only the top-level names). The adapter reads them defensively; the mapping is a SHAPE ASSUMED (components with `types`, `longText`, `shortText`; a postal address with `addressLines`, `locality`, `administrativeArea`, `postalCode`, `regionCode`) and is checked on the first real call: the adapter logs the field NAMES (never values) of the first three real answers.
- **NOT STATED:** the error body shape. Any non-2xx is "lookup unavailable": the usual flow takes over and only the HTTP status is logged.

## Key and setup
- A Google Cloud project with billing enabled and "Places API (New)" enabled. Google "strongly recommends restricting your API keys": an application restriction to the server's IP addresses/CIDR for web-service calls, plus an API restriction to Places API (New) only. A server-side key: it never reaches the web client. Setting: `Voice:Google:MapsApiKey` (secret, environment only). EEA billing addresses have different terms: the owner checks.

## Policy: OWNER DECISIONS, not resolved in code
- "You must not pre-fetch, cache, or store Places API content beyond the allowed exceptions." Place ids may be stored indefinitely; latitude and longitude may be cached for up to 30 consecutive calendar days, then deleted. **NOT STATED:** whether the caller-confirmed street address (from Place Details) may be saved into the account or the order; it depends on the Service Specific Terms (cloud.google.com, not readable from here). "Consult your legal counsel."
- Built so the saved address is the caller's own confirmed entry; nothing of Google's response, the location or anything else is kept beyond the call (not even the place id). Switch `Voice:Google:AllowSaveConfirmedAddress` (default **false**): false = the suggestion only helps (the assistant reads the address, the caller says yes, the assistant enters it the usual way through `set_delivery_address`); true = the server copies the confirmed address from the lookup into the order. Owner / legal to confirm.
- Attribution: "When displaying Places API data without a Google Map, you must include the Google logo"; new implementations use "Google Maps". Spoken use is **NOT STATED**. Conservative default: the first suggestion is introduced with "According to Google Maps" (`Voice:Google:SpokenAttribution`, default true). Owner to confirm. Never show Places data on a non-Google map: no map is shown.
