| M1-24 | 2026-11-04 | **Projection framework.** One `IProjectionHandler` per event type (a duplicate registration fails at start-up). `ProjectionStore.TryAdvanceAsync(aggregate, key, fieldGroup, createdAt, terminalState?)` implements the contract: an older event never overwrites newer state (equal times apply), a terminal state is never reopened by a non-terminal event (also across field groups of the aggregate), a later terminal event may follow a terminal one (delivered then refunded). Handlers return Applied, Skipped or **Parked(aggregateType, key)**; parked events are stored with their payload and re-applied oldest-portal-time first, each in its own transaction, claimed by a row version so concurrent replayers apply one once (the claim only matters on PostgreSQL read committed; SQLite serialises writers; the test overlaps replayers with a barrier on PostgreSQL only). `ReplayParkedAsync` is called when an aggregate appears; an hourly worker (not in Testing) sweeps all parked events and runs retention. `EventRefs` parses `data.order`/`data.booking` and returns nothing unless the marketplace id AND the portal id are both present (never match on tracking number or SKU). Known gap: a parked event whose aggregate never appears stays parked (visible by status); an operator view comes with the outbox admin endpoints. | CONTRACT.md §1.2 points 3-4. |

| M1-47 | 2026-11-04 | **Transactional outbox** (`outbox_messages`).
